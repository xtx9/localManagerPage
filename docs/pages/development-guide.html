개발 가이드

모노레포 로컬 우선 검증 중심

localManager는 하나의 앱이 아니라 여러 플랫폼을 동시에 운영하는 모노레포 프로젝트입니다. 각 플랫폼은 공통 원칙을 공유하지만, UX, 저장소, 알림 방식, 보안 요구는 서로 다릅니다.

개발은 기능 추가보다 문서와 구현 상태의 정합성을 유지하는 것이 우선입니다. 한 플랫폼의 문서가 실제 상태와 어긋나면, 사용자 경험과 작업 정확성이 모두 떨어질 수 있습니다.

핵심 개발 원칙

  • 로컬 우선 저장: 핵심 데이터는 로컬 저장소에 유지하고, 서버 의존성을 최소화합니다.
  • 사용자 주도 동기화: 자동 동기화는 기본 비활성화하고, 사용자가 직접 명시한 동기화만 허용합니다.
  • 보안 우선: 비밀정보를 로그나 코드에 남기지 않고, 로그 마스킹과 최소 권한을 적용합니다.
  • AI는 보조: 분석, 요약, 추천에 한정하고, 대규모 삭제, 배포, 과금 등 위험 행위는 제한합니다.
  • 문서와 구현 연결: 문서 상태와 실제 구현 상태를 함께 관리해야 합니다.

프로젝트 구조

디렉터리 역할
apps/ VS Code, Windows, Android, Web/PWA, Browser Extension 등 플랫폼별 앱 구현

services/ 수동 동기화와 외부 연동을 위해 분리된 서비스 수준 로직

database/ 스키마, 마이그레이션, 데이터 모델 정리
docs/ 거버넌스, 플랫폼 문서, 공개용 GitHub Pages, 작업 기록

개발 워크플로

  1. 1
    요구사항과 정책을 읽고 플랫폼 문서를 확인합니다.
  2. 2
    구현 대상이 공통 코드인지 플랫폼 코드인지 구분합니다.
  3. 3
    별도 코드와 테스트를 추가하거나 수정하고, 문서 상태를 반영합니다.
  4. 4
    검증 명령을 실행하고 결과를 작업 기록과 changelog에 정리합니다.

검증 절차

공통 검증은 루트에서, 플랫폼별 검증은 해당 앱 문서를 기준으로 실행합니다.

npm run compile:all
npm test

추가로 앱별 검증 예시는 다음과 같습니다.

  • 브라우저 확장: npm --prefix apps/05-browser-extension test
  • VS Code Extension: 해당 앱의 TypeScript compile 또는 extension host 검증
  • Android, Windows, Web/PWA: 각 플랫폼 문서의 빌드·실행 절차 준수
